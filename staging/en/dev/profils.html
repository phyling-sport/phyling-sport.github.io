Profiles: network, roaming and rates

Profiles: network, roaming and rates

This page helps you choose the network configuration and rates of your sensors for your use. It applies to Maxi-Phyling and Phyling-Live sensors; the differences are gathered at the end of the page.

Note

These settings are changed from the Live settings menu of the application (Real time tab, firmware 7.0.8 and later) or through the API: the route GET /devices/rt/{client_id}/{device_number}/profile returns the current profile, and the v1.board.profile.apply command applies it (see API - Commands (RPC)). Figures are orders of magnitude.

Hot settings or restart

A hot setting applies without restarting the sensor and without interrupting a recording. It is temporary (lost at restart) or persistent (written to the configuration), your choice.

  • Hot: acquisition, real-time and degraded rates, fallback threshold, sending rate, pausing a module, disconnection delay, roaming level, Wi-Fi band and LTE wake-up interval (Phyling-Live), targeted BLE sensor, sleep settings.
  • With restart: the network type (wifi, lte, dual), whole configuration file changes, adding a module.

Rates

A rate is set either in Hz (…Rate) or in seconds (…Delay, i.e. 1 / rate); if both are present, the delay wins.

Per module

Set in each module of the configuration (imu, gps…).

Setting (Hz / s)Role
rate / delayAcquisition rate: measurement and recording cadence. Ceiling for everything else.
realtimeRate / realtimeDelayReal-time rate: how often data is sent to the application (0 = no real time). Never tied to rate: 0 (off) or up to 200 Hz (10 Hz for GPS, 100 Hz for debug). It is kept as is, but the rate actually sent is at most rate.
realtimeLowRate / realtimeLowDelayDegraded rate: replaces the real-time rate when the network is degraded or data builds up. Same bounds as the real-time rate; kept as is, but the rate actually sent is at most the real-time rate.

Global

Set once for the whole configuration.

SettingRole
sendingRate / sendingDelayPacket sending cadence (0 = stop).
sendingLowRate / sendingLowDelayPhyling-Live: packet sending cadence when LTE is degraded. Hot-settable; 0 refused; when absent, it follows the sending cadence.
low_rate_buffer_pctFallback threshold: buffer fill level (in %) above which the sensor switches to the degraded rate. Default 0 = fallback disabled; otherwise 5 to 90% (from 1 to 4, the value is raised to 5; above 90, fallback is disabled). Same on Maxi-Phyling and Phyling-Live.
disconnect_timeoutTime without news after which the sensor is declared disconnected (30 to 600 s).

Wi-Fi and roaming

Roaming lets the sensor change Wi-Fi router when the signal weakens, or find one again after a loss.

The configured level is applied only during a recording. Outside a recording, the sensor stays at level 0 to save battery.

The levels

LevelNameUseSearch / switch (Phyling-Live)BLE cost
0DisabledMaximum savingNo search or switch based on signal strength; the sensor only searches or switches when it loses the connection to the router or the network stops working (no more internet or server access)None
1Normal (default)Fixed routersSearch below −78 dBm, switch below −80 dBmLow
2Fast reconnectionMoving between routersSearch below −68 dBm, switch below −72 dBmBusier radio: risk of BLE losses
3Discovery (race)Routers never seen, to be found very quicklySearch below −60 dBm, switch below −65 dBmHighest

The higher the level, the earlier the sensor searches and the faster it switches, at the price of power consumption and a busier radio (Wi-Fi and Bluetooth share the same antenna).

"Weak signal" = below the level's search threshold. On the Maxi-Phyling (2.4 GHz only), a tour of the channels takes about 30 s at levels 0 to 2 and 15 s at level 3.

Wi-Fi band (Phyling-Live)

The Phyling-Live can limit its search to one band: auto (2.4 and 5 GHz, default), 2.4 GHz or 5 GHz. With 2.4 GHz only, the network is found faster and searching consumes less, but 5 GHz networks are ignored.

After a loss

Each router switch cuts the connection for at least 0.7 s. In dual, at the slightest Wi-Fi latency, the Phyling-Live hands the sending over to LTE: the live data shows no latency. When Wi-Fi works poorly, both links can send in parallel.

Phyling-Live network

The network type requires a restart:

typeMeaning
wifiWi-Fi only
lteLTE-M only
dualWi-Fi and LTE together: LTE takes over as soon as Wi-Fi is absent or late. In dual, Wi-Fi or LTE can be paused hot, never both

Command latency over LTE

A command (start or stop a recording, change a setting) only reaches a sensor on LTE at its next wake-up.

NetworkCommand latency
Wi-Fiunder one second
LTEat most the wake-up interval mqtt_refresh_delay: 10 s by default, from 1 to 600 s

Shortening the interval reduces the delay but increases LTE consumption (≈ 17.5 mA then 7.8 to 9.3 mA at 10 s). On LTE, keep a disconnect_timeout clearly above the interval.

Sleep (idle_sleep)

In sleep mode, the sensor (Maxi-Phyling or Phyling-Live) stays reachable but uses less power: 50 ms green LED flash every 3 s, GPS stopped, BLE sensors disconnected and not scanned for, slowed-down processor on the Maxi. The IMU and wired modules keep running. Wi-Fi stays connected; over LTE, a command arrives as outside sleep, at the latest after the mqtt_refresh_delay wake-up interval.

No sleep in hotspot mode, nor while a recording upload is pending (retries included). Automatic sleep also waits for the end of a cloud BLE scan. Requesting sleep during an upload is refused (busy).

  • Entering: automatically after 30 min without activity (state change, button press, BLE scan, upload request, settings or calibration change), or from the application (⋮ menu → Power → "Put to sleep") or the API ("state": "idle_sleep", which stops a running recording).
  • Leaving: pressing REC (without starting a recording) or ON/OFF, the "Wake up" button of the application, starting a recording or a scenario, a calibration change, a BLE scan, a recording upload, a firmware update, or the API ("state": "idle" or "record").
  • Settings (hot, "Sleep" section of the advanced settings):
